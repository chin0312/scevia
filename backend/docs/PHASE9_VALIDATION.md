## Evaluation rights and access decisions

- **Polymarket.** The API documentation describes public Gamma discovery, CLOB quotes/history and market WebSocket, and public Data API wallet/market routes. The [V2 Data API docs](https://data-api.polymarket.com/v2/docs) document a default three-year floor for certain account reads. That is a documented query rule and actual coverage remains unmeasured. The [Terms of Use, prohibited uses](https://polymarket.com/tos) restrict access/use of raw or derived data by covered Capital Market Clients and market data distributors, including through APIs or on-chain, absent written agreement. They separately restrict certain redistribution and commercial exploitation. Scevia's classification and permitted internal evaluation need confirmation. [Institutional guidance](https://institutional.polymarket.com/) directs covered data customers to `data-licensing@polymarket.com`. Neither the [developer help page](https://help.polymarket.com/en/articles/13364254-does-polymarket-have-an-api) nor the [Builder code](https://builders.polymarket.com/code-of-conduct) grants an exception for this use. Regional eligibility, retention and external display should be asked separately. Contract inspections below are independent chain deployment and DEX checks. They did not extract market, condition, account, or payout data from Polymarket.
- **Kalshi.** [Public market API documentation](https://docs.kalshi.com/getting_started/quick_start_market_data) describes keyless discovery, and [historical data docs](https://docs.kalshi.com/getting_started/historical_data) describe archived markets/trades/candles and the moving archive cutoff. [Data terms §§ I–II](https://kalshi-public-docs.s3.amazonaws.com/kalshi-data-terms-of-service.pdf) exclude software development without written consent from personal noncommercial use and separately restrict derived valuation or portfolio services. No separate blanket evaluation grant for Scevia was found. [Institutional Data](https://institutional.kalshi.com/data) explicitly offers portfolio monitoring and historical research and lists `institutional@kalshi.com`. Request a data-only evaluation scope. Archived Kalshi discovery depth and Polymarket V2 position/CLOB-token/condition mappings need real payloads. Ask `team@predexon.com` to identify upstream grants, what free evaluation may retain, and whether portfolios/derived results and public displays are covered before using it as the venue source. - **Prediction.com.** [Quickstart](https://prediction.com/api/docs/quickstart) documents account/key creation. ## Verified live ECB path

After reviewing the ECB reuse conditions, run from `backend`:

```sh
npx --no-install tsx scripts/validate-ecb-live.ts --confirm-ecb-reuse
```

The runner applies the existing migrations in a disposable database, acquires from the two fixed HTTPS paths, invokes the existing canonical ECB ingestion and queries the normal authenticated HTTP routes through Fastify. It requires no external PostgreSQL instance, production credentials or provider authorizations. It never writes to an existing database, never enables a background provider worker and stays outside deterministic CI.

- Daily and 90-day downloads returned HTTP 200 and **1,547 / 69,496 bytes**. In the final run they took **44 / 25 ms** from acquisition through response consumption. A separate direct curl probe took **69 / 50 ms**. These are one-host observations with unknown upstream cache effects.
- Daily and archive ingest together stored **256 unique canonical rows** across **64 observation dates**, **28 August–25 November 2026**, for USD, GBP and the retained SGD/MYR support. The date envelope does not establish intraday coverage. Weekend sampling on 22 November reused the 20 November GBP observation. Earlier retrospective selection used archive evidence at its dated cutoff. The matching conservative knowledge-time query withheld the rate because local retrieval occurred later.
- The published latest EUR values were USD **1.0935** and GBP **0.83730**. An independent decimal calculation gives USD→EUR approximately **0.914495** and USD→GBP approximately **0.765706**. The HTTP API returned those directions and two frozen legs for the cross. [ECB published reference data](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)
- A native **USD 100** virtual-cash Replay with GBP reporting started near **GBP 73.62** and ended near **GBP 76.57**, with **91 chart points**. It matched the independent ECB ratio and survived save/readback. Local API injection took **57 ms** for evaluation. This establishes the cash-and-FX path. It does not establish Replay with actual market instruments, historical fills, provider fees or payout.
- ECB's observed feeds matched the existing XML adapter, so there was no evidence-based reason to change its normalization. Keep publication and retrieval clocks separate. No invented rates, raw responses, credentials or financial statements were committed.

### Annual ECB extension

Append `--annual` to the command above. The runner requests a rolling 365-day interval from the [ECB Data Portal EXR API](https://data.ecb.europa.eu/help/api/data-examples), using a compact CSV response for daily USD and GBP per EUR. It rejects unexpected columns, series or date bounds. USD and GBP are synthetic conversion outputs when derived by inversion or crossing. The annual endpoint returned HTTP 200 and **29,244 bytes**. Daily plus archive yielded **512 unique rows** across **255 dates**, 26 November 2025–25 November 2026, including the existing daily SGD/MYR rows. The independent ratio check and the **366-point** frozen Replay agreed at **£75.81 → £76.57** on virtual USD 100. The development worker checks once at startup and after the weekday publication window. After 16:00 UTC, an older but valid feed can trigger one-hour retries until 18:00 UTC, then the worker waits until the next weekday. This bounds extra holiday reads without an external calendar. Empty or invalid data enters the hourly failure path. A successful current-day observation resumes normal scheduling.

For normal annual ingestion, point the loopback development configuration at a permitted database and run `ECB_FX_REFERENCE_AUTHORIZED=YES FX_ARCHIVE_AUTHORIZED=YES npm run fx:archive -- ecb-annual` from `backend`. The `ecb` command still acquires the 90-day XML archive. Daily acquisition retains internal SGD/MYR support.

### Reusable stablecoin acquisition and measured archive

The adapter uses the exact Polygon contracts published by [Circle](https://developers.circle.com/stablecoins/usdc-contract-addresses) and [Polymarket](https://docs.polymarket.com/resources/contracts). It accepts six-decimal records only under their contract keys and carries USD aggregate methodology, observation time and local retrieval time. Native USDC is distinct from USDC.e. Its vendor first-price result dates to 4 October 2018, before [Circle's native Polygon USDC launch](https://www.circle.com/blog/native-usdc-now-available-on-polygon-pos). The adapter excludes pre-launch observations and treats that first result as broader vendor lineage. The pUSD first-price endpoint reported **28 April 2026 15:13:12 UTC**, the earliest returned by DefiLlama for that contract. The first eligible daily chart sample was 28 April 2026 23:59 UTC. Neither establishes deployment time or an earliest traded price across all sources.

Optional live archive validation uses a disposable database:

```sh
npx --no-install tsx scripts/validate-ecb-live.ts --confirm-ecb-reuse --annual --confirm-defillama-evaluation --defillama-coverage
```

All chart requests ended at 26 November 2026 00:00 UTC and requested 1-day spacing. The provider accepts only one of `start` or `end`, and caps combined points per request at 500. An initial two-token 365-day call returned HTTP 400. The adapter acquires the annual interval in two windows of 250 and 115 daily anchors. Observation clocks are the actual vendor timestamps, which may be offset from the requested daily anchors. It excludes out-of-window observations without substituting parity.

| Requested lookback (UTC) | Eligible USDC samples | Eligible pUSD samples | Successful requests, response bytes and observed latency |
| --- | ---: | ---: | --- |
| 30 days, from 28 Oct 2026 | 30 | 29, from 28 Oct 23:52:55 | 1, 3,342 bytes, 302 ms |
| 90 days, from 29 Aug 2026 | 90 | 89, from 29 Aug 23:51:50 | 1, 9,567 bytes, 935 ms |
| 365 days, from 27 Nov 2025 | 365, from 27 Nov 00:00:02 | 212, from 28 Apr 23:59:00 2026 | 2, 24,191 and 6,089 bytes, 505 and 300 ms |

The 30- and 90-day pUSD responses each included one point just before the requested opening cutoff. The earlier portion of the annual pUSD window had no eligible observations. The latest pUSD chart point was 421 seconds before the end anchor. The latest USDC point matched the end anchor. These are single-run measurements, and daily sampling does not establish intraday coverage. Chart confidence was 0.99 for each returned series. The [public API reference](https://api-docs.defillama.com/) does not specify a confidence calibration sufficient to validate financial accuracy or executable liquidity. The 0.95 threshold is a local admission heuristic. The 25-hour eligibility window permits daily spacing with small timestamp offsets and exposes older eligible observations as stale last-known evidence. Reports preserve native values and withhold nonzero conversions without an eligible rate. Frozen reports keep their stored revisions.

With permission for storage in the target database, run the following one-off commands on loopback in development. The dual flags are execution controls. No recurring DefiLlama worker is configured. Set disposal or retention for the approved database and confirm rights before retaining, displaying, or automating the data.

```sh
DEFILLAMA_FX_ACQUISITION_AUTHORIZED=YES FX_ARCHIVE_AUTHORIZED=YES npm run fx:archive -- defillama-current
DEFILLAMA_FX_ACQUISITION_AUTHORIZED=YES FX_ARCHIVE_AUTHORIZED=YES npm run fx:archive -- defillama 365
```

Both assets share each request. HTTP 429 stops the command and surfaces `Retry-After` when available. If ongoing acquisition is approved, one shared hourly request for both assets would be roughly 720 per 30 days, plus explicit archives. Actual quotas and suitable cadence remain unverified. Automatic FX selection can use eligible DefiLlama rows and fall back when another preferred source is unavailable. CoinGecko/Kraken remain alternatives. Phase 10 may offer a DefiLlama family preference spanning the two exact-asset USD legs if usage rights support that choice.
