## Evaluation rights and access decisions

- **Polymarket.** The API documentation describes public Gamma discovery, CLOB quotes/history and market WebSocket, and public Data API wallet/market routes. The [V2 Data API docs](https://data-api.polymarket.com/v2/docs) document a default three-year floor for certain account reads. That is a documented query rule and actual coverage remains unmeasured. The [Terms of Use, prohibited uses](https://polymarket.com/tos) restrict access/use of raw or derived data by covered Capital Market Clients and market data distributors, including through APIs or on-chain, absent written agreement. They separately restrict certain redistribution and commercial exploitation. Scevia's classification and permitted internal evaluation need confirmation. [Institutional guidance](https://institutional.polymarket.com/) directs covered data customers to `data-licensing@polymarket.com`. Neither the [developer help page](https://help.polymarket.com/en/articles/13364254-does-polymarket-have-an-api) nor the [Builder code](https://builders.polymarket.com/code-of-conduct) grants an exception for this use. Regional eligibility, retention and external display should be asked separately. Contract inspections below are independent chain deployment and DEX checks. They did not extract market, condition, account, or payout data from Polymarket.
- **Kalshi.** [Public market API documentation](https://docs.kalshi.com/getting_started/quick_start_market_data) describes keyless discovery, and [historical data docs](https://docs.kalshi.com/getting_started/historical_data) describe archived markets/trades/candles and the moving archive cutoff. [Data terms §§ I–II](https://kalshi-public-docs.s3.amazonaws.com/kalshi-data-terms-of-service.pdf) exclude software development without written consent from personal noncommercial use and separately restrict derived valuation or portfolio services. No separate blanket evaluation grant for Scevia was found. [Institutional Data](https://institutional.kalshi.com/data) explicitly offers portfolio monitoring and historical research and lists `institutional@kalshi.com`. Request a data-only evaluation scope. Private account API auth and export consent are separate. Evaluation availability, quotas and price are quote-dependent.
- **Predexon.** The [quickstart](https://docs.predexon.com/) links signup and key creation. The [Free plan](https://predexon.com/pricing) advertises $0, 1 request/sec, 1,000 premium requests/month, unmetered eligible historical REST and no WebSocket. Tick downloads are a separate product and may require credits/payment setup. Dev is listed at $49/month. Documentation advertises Polymarket and Kalshi, indexed execution and history. Archived Kalshi discovery depth and Polymarket V2 position/CLOB-token/condition mappings need real payloads. Ask `team@predexon.com` to identify upstream grants, what free evaluation may retain, and whether portfolios/derived results and public displays are covered before using it as the venue source. No authorized keyless market-data path established.
- **Prediction.com.** [Quickstart](https://prediction.com/api/docs/quickstart) documents account/key creation. [Free](https://prediction.com/api) lists $0 with no credit card, 1 request/sec, 1,000 requests/month, and 10 matched-market requests/month. Dev is listed at $49/month. [API terms §§ 6–7](https://prediction.com/terms-of-service) allow internal use or display within the end-user app subject to plan and require upstream venue compliance. They restrict standalone competing aggregation/historical databases. [API docs](https://prediction.com/api/docs) advertise events, bulk prices and historical candles. Exact native identities, archive depth, caching and data rights need verification. Algorithmic event matches cannot be used as settlement or instrument identity. Ask through [API support](https://prediction.com/contact) if Predexon/native coverage or rights fall short.
- **Stablecoins.** [DefiLlama documents an open API](https://docs.llama.fi/faqs/frequently-asked-questions) and explicitly supports keyless exact-chain price probes. The samples below use [documented public routes](https://api-docs.defillama.com/) for bounded internal validation. Open access does not establish upstream rights for public display or indefinite retention. [DEX Screener API terms §§ 1–4](https://docs.dexscreener.com/api/api-terms-and-conditions) permit commercial and noncommercial use within competing-product/resale restrictions. Its [token-pair reference endpoint](https://docs.dexscreener.com/api/reference) supports keyless corroboration, but these payloads lacked price observation timestamps. [GeckoTerminal](https://api.geckoterminal.com/docs/index.html) advertises keyless beta access at 30 calls/minute. Its [site terms §§ 3.3, 4.4–4.5](https://www.geckoterminal.com/terms-conditions) distinguish API-specific terms from personal-use site content. Scevia's API retention and display terms remain unconfirmed, so it was unnecessary to probe. [CoinGecko Demo](https://www.coingecko.com/en/api/pricing) requires a free key and has no commercial license. Its [contract chart endpoint](https://docs.coingecko.com/demo/reference/contract-address-market-chart) documents up to 365 days. The existing adapter was not called. [Kraken API notices](https://docs-legacy.kraken.com/api/docs/guides/global-intro/#notices) require prior permission for nonpersonal commercial use of public market data. Its existing [closed OHLC path](https://docs.kraken.com/api-reference/market-data/get-ohlc-data) is limited to 720 recent candles. No Kraken call was needed.

## Verified live ECB path

After reviewing the ECB reuse conditions, run from `backend`:

```sh
npx --no-install tsx scripts/validate-ecb-live.ts --confirm-ecb-reuse
```

The runner applies the existing migrations in a disposable database, acquires from the two fixed HTTPS paths, invokes the existing canonical ECB ingestion and queries the normal authenticated HTTP routes through Fastify. It requires no external PostgreSQL instance, production credentials or provider authorizations. It never writes to an existing database, never enables a background provider worker and stays outside deterministic CI.

- Daily and 90-day downloads returned HTTP 200 and **1,547 / 69,496 bytes**. In the final run they took **44 / 25 ms** from acquisition through response consumption. A separate direct curl probe took **69 / 50 ms**. These are one-host observations with unknown upstream cache effects.
- Daily and archive ingest together stored **256 unique canonical rows** across **64 observation dates**, **28 August–25 November 2026**, for USD, GBP and the retained SGD/MYR support. The date envelope does not establish intraday coverage. Weekend sampling on 22 November reused the 20 November GBP observation. Earlier retrospective selection used archive evidence at its dated cutoff. The matching conservative knowledge-time query withheld the rate because local retrieval occurred later.
- The published latest EUR values were USD **1.0935** and GBP **0.83730**. An independent decimal calculation gives USD→EUR approximately **0.914495** and USD→GBP approximately **0.765706**. The HTTP API returned those directions and two frozen legs for the cross. [ECB published reference data](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)
- A native **USD 100** virtual-cash Replay with GBP reporting started near **GBP 73.62** and ended near **GBP 76.57**, with **91 chart points**. It matched the independent ECB ratio and survived save/readback. Local API injection took **57 ms** for evaluation. This establishes the cash-and-FX path. It does not establish Replay with actual market instruments, historical fills, provider fees or payout.
- ECB's observed feeds matched the existing XML adapter, so there was no evidence-based reason to change its normalization. Keep publication and retrieval clocks separate. No invented rates, raw responses, credentials or financial statements were committed.

### Annual ECB extension

Append `--annual` to the command above. The runner requests a rolling 365-day interval from the [ECB Data Portal EXR API](https://data.ecb.europa.eu/help/api/data-examples), using a compact CSV response for daily USD and GBP per EUR. It rejects unexpected columns, series or date bounds. USD and GBP are synthetic conversion outputs when derived by inversion or crossing. The annual endpoint returned HTTP 200 and **29,244 bytes**. Daily plus archive yielded **512 unique rows** across **255 dates**, 26 November 2025–25 November 2026, including the existing daily SGD/MYR rows. The independent ratio check and the **366-point** frozen Replay agreed at **£75.81 → £76.57** on virtual USD 100. The development worker now checks after publication on weekdays following a successful request, with hourly retries on failure and one startup check. Holidays can produce eligible prior references. Archive acquisition remains explicit.

## Verified stablecoin and Polygon paths

```sh
npx --no-install tsx scripts/validate-ecb-live.ts --confirm-ecb-reuse --annual --confirm-defillama-evaluation
npx --no-install tsx scripts/validate-polygon-public.ts --confirm-public-rpc-evaluation
```

- DefiLlama returned the exact Polygon pUSD and Circle-native USDC contract keys, six decimals, timestamps, price and confidence. The isolated run stored eligible samples with actual retrieval clocks, read them through authenticated `GET /v1/fx/reference` and valued **100 pUSD + 100 USDC at USD 199.90110388105895** using the canonical reporting calculation. Source inputs were **0.9991275056605895** and **0.99988353315**. The December 2025 query returned a USDC reference **0.9997511246514444** and omitted pUSD. The October 2026 snapshot returned both assets, including pUSD **0.9996439425333847**. This tests sampled retrospective access and preserves the conservative knowledge-time restriction. It establishes neither an uninterrupted archive nor a tradable price. The trial does not introduce a collector or preference option. [Circle contract reference](https://developers.circle.com/stablecoins/usdc-contract-addresses)
- DEX Screener returned an exact pUSD/bridged USDC.e Uniswap pool. Its indicated pUSD USD figure differed from the DefiLlama sample. Pool activity was only three transactions and about $1.54 reported volume over 24 hours. The exact USDC token had a separate pool with thousands of transactions. The DEX endpoint did not supply the applicable observation timestamp for its quoted price. The pool-level numbers were not imported. Its pUSD/USDC.e ratio alone cannot establish a pUSD/USD rate.
- [1RPC](https://docs.1rpc.io/overview/supported-networks) returned chain 137 and a finalized block. A pinned `eth_getCode` returned historical state unavailable. [PublicNode](https://polygon.publicnode.com/) supported the finalized pin, the [official PositionManager](https://docs.polymarket.com/resources/contracts) EIP-1967 implementation address and deployed code, pUSD's decimal call and its pool's token order. A bounded 128-block address/topic lookup found a Uniswap Swap whose receipt block hash, success status and log identity were independently matched. The runner repeats the exact deployment and receipt checks without log scans, secrets, wallet actions or account-level data. The pool is pUSD/USDC.e. The sample receipt is a public DEX transaction. It provides no evidence of Polymarket settlement or an actual account entitlement.
- [Polymarket on-chain position docs](https://docs.polymarket.com/resources/onchain-position-data) distinguish module routing, identifiers and migration/redemption events. Resolving a production payout still requires a reviewed exact condition/module, collateral, outcome index, payout event/state and effective/finalized time, with at least one independently verified example for the supported route. The proxy match confirms deployed identity. Existing payout support was preserved.
