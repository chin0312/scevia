# Data acquisition strategy

Scevia owns accounting, reconciliation, analytics, risk and simulation. Select providers by evidence capability. Financial postings require native economic identity and account attribution, even if a third party discovered the evidence. Preserve source clocks, denomination, availability and original evidence. An aggregator's P&L or cross-venue event grouping is supplementary research.

## Provider selection and cost

- Predexon is the first aggregator trial for native-ID discovery and historical data. Verify free endpoint eligibility, Kalshi title and resolved-market coverage, native V2 identifiers, trade and orderbook depth, wallet candidate coverage and permitted use separately. Prediction.com provides a second search and orderbook candidate. An API plan and market data rights are separate questions.
- Use an approved HyperSync export across an exact Polygon block window to test indexed discovery before committing to a service. Compare each generation's supported contract and topics against finalized receipts. Goldsky, The Graph and SQD are alternatives if they cover the exact deployment. Alchemy transfer indexes and QuickNode archival RPC can supplement discovery and proof. Dune is suitable for offline corroboration. None establishes account attribution or posting by itself. [Goldsky](https://docs.goldsky.com/introduction) · [The Graph](https://thegraph.com/docs/en/) · [SQD](https://docs.sqd.dev/en/home) · [Alchemy transfers](https://www.alchemy.com/docs/data/transfers-api/transfers-endpoints/alchemy-get-asset-transfers) · [QuickNode logs](https://www.quicknode.com/docs/polygon/eth_getLogs) · [Dune](https://docs.dune.com/api-reference/overview/introduction)
- GeckoTerminal can corroborate exact token and pool identity, trading volume, liquidity and OHLC. Reject raw pool parity as a fiat conversion. DefiLlama exact-chain USDC and pUSD references passed bounded evaluation. Ongoing retention, display and quota scope remain open. Contractual redemption may be modeled separately when supported by verified collateral conversion evidence. [GeckoTerminal](https://www.geckoterminal.com/dex-api) · [DeFiLlama](https://api-docs.defillama.com/) · [Polymarket pUSD](https://docs.polymarket.com/concepts/pusd)
- One shared hourly current collector uses 720–744 requests per 30–31 days, per enabled hourly source. Separate schedules in multiple processes would multiply calls. Budget archive calls independently. No paid plan is required by the code. Confirm Demo limits and public display rights before choosing a CoinGecko deployment plan. Benchmark RPC cost by receipt and block reads, and market acquisition by unique native markets. No actual operating cost or achieved latency has been measured. [CoinGecko plans](https://www.coingecko.com/en/api/pricing)

## Live-data acceptance checklist

See the [Phase 9 maintainer checklist](PHASE9_VALIDATION.md#maintainer-actions-by-stage) for the access decisions and inquiry drafts. Obtain one authorized venue path first. Put any approved credentials in local configuration outside Git and CI.

### First authorized market evaluation

1. Use a disposable loopback development database and migrate with `npm run db:migrate`, then start `npm run dev`. Enable only the authorized `POLYMARKET_LIVE_DATA_AUTHORIZED` or `KALSHI_PUBLIC_DATA_AUTHORIZED` flag and set the approved `KALSHI_ENVIRONMENT` if applicable. For temporary quote acquisition, use `CONTINUOUS_TRACKING_ENABLED=YES` with approved `MARKET_TRACKING_RETENTION_DAYS`. Leave private-account flags disabled.
2. Discover one approved real market in the existing provider catalog. Send authenticated `POST /v1/market-evidence` with `{ provider, market, follow: true }`, where `market` is the actual condition ID or ticker. Record its canonical outcome ID, native identifier, settlement asset, lifecycle, and exact trading window where established. Read `GET /v1/market-references?instruments=<instrumentId>` for the stored quote and its timestamp. Submit `{ instrumentId, from, through }` to `POST /v1/market-references/history` and follow the returned cursor when needed. Verify the actual archive bounds and provenance.
3. Send `POST /v1/simulations` and use the returned collection ID under `/v1/simulations/<id>/scenarios`. Preview with `POST /baseline` using `mode: "scratch"`, the actual native asset, current `asOf`, `catalog: [instrumentId]`, and a virtual cash bucket with the matching venue. Evaluate via `POST /evaluate` with that baseline token and a hypothetical buy with explicit fee and execution assumptions. Compare units, cash and value against independent arithmetic. Save with the reviewed `baselineToken`, source and inputs. Confirm an identical frozen read after fresh quote acquisition. See [Scenario API](SCENARIOS.md).
4. Use [Historical Replay](HISTORICAL_REPLAY.md) from the same collection. Use actual historical observation and eligibility cutoffs, explicitly assumed fees, and hypothetical entry/exit. Independently check ending cash, value and return. Save the preview token and verify readback. Repeat with one approved resolved market. Keep unsupported settlement unavailable until the exact module, outcome and payout are verified.
5. Select the tested active and resolved markets for a proposed local Demo. Use `npm run demo:dataset -- capture /absolute/path/to/approved-plan.json /absolute/path/to/authorized-demo.json` and `npm run demo:dataset -- validate /absolute/path/to/authorized-demo.json`. Set `DEMO_CAPTURE_AUTHORIZED=YES` and `DEMO_DATASET_PATH` to the authorized path, then use authenticated `POST /v1/demo`. Compare virtual trades and supported payout results against independent calculations. [Demo setup](DEMO.md)
6. For a licensed aggregator, run its official evaluation quickstart with approved inputs, record raw shape privately if allowed, and compare exact native IDs and timestamps before adapting any provider response. The current routes acquire from authorized native adapters. Aggregator live ingestion requires validated samples first.

For fiat and stablecoin CLI commands, archive measurements and authorization scope, use the [Phase 9 FX report](PHASE9_VALIDATION.md#reusable-stablecoin-acquisition-and-measured-archive).

### Required for actual portfolio tracking

1. Supply an approved populated Polymarket wallet, bounded historical range and permitted Polygon RPC URL. Set `POLYMARKET_POLYGON_RPC_AUTHORIZED=YES` and `POLYMARKET_POLYGON_RPC_URL`. Set `TRACKED_PROVIDER_ACCOUNT_IDS` only to approved backend account UUIDs. For Kalshi use approved read-only `KALSHI_ACCOUNT_DATA_AUTHORIZED=YES`, the matching `KALSHI_ENVIRONMENT`, `KALSHI_PROVIDER_ACCOUNT_ID`, `KALSHI_PORTFOLIO_ID`, `KALSHI_KEY_ID` and `KALSHI_PRIVATE_KEY_FILE`, or a permitted native export. RPC provider quotas, fees and account/export permissions need operator confirmation.
2. Against independent statements, run authenticated `POST /v1/provider-accounts/<account-id>/sync?scope=current` and `?scope=history` twice, and compare cash, positions, trades, fees, rebates, settlement and redemption. With `POLYMARKET_RECEIPT_DISCOVERY_AUTHORIZED=YES`, run `npm run verify:polymarket-account-receipts -- <account-id> <from-ISO> <through-ISO> [approved-index-file.json]` for a window of up to seven days. Review the finalized log-level proposals and unresolved rows locally. Verify market-only valuation updates, interrupted worker recovery and frozen scenario readback. Keep credentials, wallet identifiers and statements outside Git, CI and public PRs.

Record the verified archive period, applicable fee and payout evidence, successful reconciliation and Demo results, request volumes, observed quotas and costs. Technical fixture results do not substitute for this Phase 9 acceptance record.

### Optional supplementary trials

- Trial Predexon discovery and history against exact Kalshi and Polymarket IDs, HyperSync candidate exports against finalized receipts, and GeckoTerminal exact Polygon token and pool corroboration. Verify plan-specific scope, quotas and reuse before calling any service. Predexon lists a free core tier and reserves streaming for paid plans. No paid subscription has been approved. Prediction.com, Frankfurter and the other candidates are optional where they address a measured evidence gap.

## Reporting contract

Phase 10 Settings will initially offer USD (default), EUR and GBP. The backend also supports SGD and MYR for API use, historical records and saved results. Provider-native settlement assets remain USD, USDC and PUSD. Reporting selection changes presentation and does not change native funding or settlement.

`PUT /v1/preferences/reporting` takes `currency` and optional `fiatSource` and `stablecoinSource`. The supported choices are `ecb_euro_reference`, `kraken_usdc_usd_ohlc`, and the `coingecko_polygon_pusd_usd` family. Null restores automatic selection. These preferences select from eligible stored evidence and do not enable a collector or grant data rights. A CoinGecko daily source alias selects the same family. Eligibility excludes stale rates before ranking. If that family has no eligible reference for a leg, another eligible source can be used with `fallback: true`. Each leg retains its exact source. A stale direct rate may be shown separately as qualified last-known evidence. Same-source conflicts are surfaced, and covered daily observations are indicative. None of these references promises executable pricing.

A confirmed zero contributes zero without a rate. Unknown amounts, missing financial coverage and nonzero amounts without an eligible rate remain unavailable. An unrepresented connected account makes the complete current portfolio value unavailable and preserves eligible known subtotals. New single- and mixed-denomination scenarios default to the global reporting currency unless overridden, and save freezes the chosen evidence.

Ordinary history defaults to retrospective reconstruction. Knowledge mode uses current records' acquisition and revision clocks conservatively. Consolidated history withholds ineligible values, returns and native breakdowns. Single-denomination performance returns `financial_knowledge_time_unavailable` when the requested range depends on late evidence or revisions it cannot reconstruct. This mode does not reconstruct a full revision history or establish unbiased strategy testing.

## Phase 8 handoff

Historical Replay within Scenario Lab can reuse independent ownership, user-defined virtual working capital, current discovery, bounded market backfill, shared historical FX, verified native identity, trading-window and eligible payout evidence, canonical ledger and performance methods, consolidated reporting and frozen scenario persistence. It requires no trading account or personal history. Remaining gates include demonstrated archive coverage and trading windows for real markets, retention rights, and supported finalized settlement evidence. Current-generation Polymarket PositionManager, disputed or nonstandard payouts, and other unverified resolution cases remain unresolved.

The [Phase 9 validation report](PHASE9_VALIDATION.md) records actual exact-token reference and public Polygon probes, annual ECB coverage, trial terms, and provider inquiry drafts. Use one approved market-data source first. The keyless FX and RPC probes need no account or paid key. They do not confer rights to venue markets or public redistribution.
