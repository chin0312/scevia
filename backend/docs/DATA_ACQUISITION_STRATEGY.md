# Data acquisition strategy

Scevia owns accounting, reconciliation, analytics, risk and simulation. Select providers by evidence capability. Financial postings require native economic identity and account attribution, even if a third party discovered the evidence. Preserve source clocks, denomination, availability and original evidence. An aggregator's P&L or cross-venue event grouping is supplementary research.

## Provider selection and cost

- Predexon is the first aggregator trial for native-ID discovery and historical data. Verify free endpoint eligibility, Kalshi title and resolved-market coverage, native V2 identifiers, trade and orderbook depth, wallet candidate coverage and permitted use separately. Prediction.com provides a second search and orderbook candidate. An API plan and market data rights are separate questions.
- Use an approved HyperSync export across an exact Polygon block window to test indexed discovery before committing to a service. Compare each generation's supported contract and topics against finalized receipts. Goldsky, The Graph and SQD are alternatives if they cover the exact deployment. Alchemy transfer indexes and QuickNode archival RPC can supplement discovery and proof. Dune is suitable for offline corroboration. None establishes account attribution or posting by itself. [Goldsky](https://docs.goldsky.com/introduction) · [The Graph](https://thegraph.com/docs/en/) · [SQD](https://docs.sqd.dev/en/home) · [Alchemy transfers](https://www.alchemy.com/docs/data/transfers-api/transfers-endpoints/alchemy-get-asset-transfers) · [QuickNode logs](https://www.quicknode.com/docs/polygon/eth_getLogs) · [Dune](https://docs.dune.com/api-reference/overview/introduction)
- GeckoTerminal can corroborate exact token and pool identity, trading volume, liquidity and OHLC. Reject raw pool parity as a fiat conversion. DeFiLlama is a candidate only once exact-chain asset coverage and source methodology are verified. Contractual redemption may be modeled separately when supported by verified collateral conversion evidence. [GeckoTerminal](https://www.geckoterminal.com/dex-api) · [DeFiLlama](https://api-docs.defillama.com/) · [Polymarket pUSD](https://docs.polymarket.com/concepts/pusd)
- One shared hourly current collector uses 720–744 requests per 30–31 days, per enabled hourly source. Separate schedules in multiple processes would multiply calls. Budget archive calls independently. No paid plan is required by the code. Confirm Demo limits and public display rights before choosing a CoinGecko deployment plan. Benchmark RPC cost by receipt and block reads, and market acquisition by unique native markets. No actual operating cost or achieved latency has been measured. [CoinGecko plans](https://www.coingecko.com/en/api/pricing)

## Operator acceptance

1. Confirm endpoint, credentials, purpose, source attribution, permitted storage period and redisplay for the proposed use. Start with current and historical public reference data, then add approved read-only account or export evidence. Keep private configuration outside Git and CI.
2. On an authorized loopback development deployment, configure `ECB_FX_REFERENCE_AUTHORIZED=YES`, `KRAKEN_USDC_REFERENCE_AUTHORIZED=YES`, or `COINGECKO_PUSD_REFERENCE_AUTHORIZED=YES` with `COINGECKO_DEMO_API_KEY` as applicable. Set `FX_REFERENCE_RETENTION_DAYS` within the approved shared limit. Run `npm run db:migrate` and `npm run dev`. Inspect authenticated `GET /v1/fx/reference?base=PUSD&currency=USD` for the exact contract, a positive vendor rate, timestamps and source. Compare against independent exact-token evidence. Review low-liquidity and outlier cases before relying on the source.
3. Run `FX_ARCHIVE_AUTHORIZED=YES npm run fx:archive -- coingecko-pusd` (or `ecb`, `kraken`). Check the actual time span returned and compare retrospective and knowledge-mode queries for a date before local retrieval. Use `PUT /v1/preferences/reporting` with `currency` and optional `fiatSource` or `stablecoinSource` source names, with null restoring automatic selection. A missing/stale preferred source may fall back with its own provenance. Validate a saved scenario stays frozen across preference changes.
4. Select an approved enabled Polymarket wallet, date window and Polygon RPC endpoint. Configure `POLYMARKET_POLYGON_RPC_AUTHORIZED`, `POLYMARKET_POLYGON_RPC_URL`, and `POLYMARKET_RECEIPT_DISCOVERY_AUTHORIZED`. Run `npm run verify:polymarket-account-receipts -- <account-id> <from-ISO> <through-ISO> [approved-index-file.json]`. Use up to seven days and up to 500 candidate rows with `chainId`, `exchange`, `wallet`, `transactionHash`, `logIndex`, `provider` and `occurredAt`. The tool verifies up to 12 missing receipts per run, caches finalized results and leaves exact proposals for review. Index records alone cannot post a financial event.
5. Supply an approved populated Kalshi read-only account or native export, equivalent Polymarket records and independent statements for fees, rebates, cash, positions and redemptions. Validate repeated sync and late evidence. Supply approved active and resolved demo markets with independent expected simulated results. Follow the commands in [Continuous Tracking](CONTINUOUS_TRACKING.md). Keep Phase 7 open until actual reconciliation, live evidence coverage and demo acceptance are recorded.

Phase 8 reuses the same identity, provenance and time semantics for Historical Replay within independently funded Scenario Lab. Retrospective reconstruction does not imply every superseded record and decision can be reconstructed in knowledge-time mode.
